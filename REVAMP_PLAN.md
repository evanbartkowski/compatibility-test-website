# Truth Desire experience revamp

## Findings

The existing Next.js application has useful assessment, guest session, invitation, export, and optional account infrastructure. The homepage buries its broad discovery purpose beneath mature content and repeated directories. Two browse pages duplicate the same task. The visual hierarchy relies on small text and too many competing actions. Population statistics only accept numeric enjoyment answers, leaving personality and other question formats without useful category benchmarks. Compatibility can treat unmeasured default dimensions as evidence and expose category values in hidden explanations.

## Direction

Use a quiet black canvas (#09090f), layered charcoal (#12121c), near-white (#f4f2ff), violet (#a78bfa), cyan (#67e8f9), and restrained rose (#f9a8d4). Figtree carries both expressive headlines and readable body text; tabular numerals serve scores. A distinctive overlapping orbital profile visual represents personal identity and connection, with restrained motion and an explicitly labeled example.

Homepage composition: left-aligned introduction and paired actions beside the profile visual; a compact four-purpose strip; curated assessment cards; two comparison demonstrations; short/full choice and a simple three-step explanation. The library uses a searchable card grid with category filters. Existing assessment and results mechanics retain their data and receive clearer hierarchy and consistent surfaces.

```text
Navigation                     Primary action
Introduction + two choices     Interactive profile
Four discovery outcomes across the page
Curated assessment grid
Partner comparison             Community perspective
Test-depth explanation         Quick / full choices
Three-step explanation
Closing action
```

## Implementation

1. Establish shared tokens, navigation, cards, controls, and responsive layouts.
2. Replace the homepage and consolidate test discovery into one library.
3. Improve question navigation, scoring transparency, and draft continuity.
4. Add measured category benchmarks, empirical percentiles, sufficient-sample states, and deduplicated/version-compatible cohorts.
5. Correct empty compatibility and sharing behavior, and improve comparison visuals.
6. Validate scoring, guest assessment, resume/edit, results/export, invite comparison, filters, keyboard access, and mobile layouts.

## Data boundaries

Show real opted-in test-taker cohorts as community comparisons, never as representative general-population norms. Keep synthetic examples labeled and separate. Preserve guest-first use and optional configured email/account integrations. Work in the existing checkout; production deployment is outside this local redesign.
